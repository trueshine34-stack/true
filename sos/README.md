# Sos.

Одна лента вместо трёх — приложение собирает посты и чаты из **Telegram**,
**Instagram** и **Threads** в единую ленту. Клиент представляет собой
одностраничное веб-приложение (`index.html`), которое нативная Android-оболочка
(`MainActivity`, WebView) загружает из `file:///android_asset/index.html`.

## Авторизация

Демо-авторизация реализована единым сценарием для всех трёх сетей. Данные
никуда не отправляются и хранятся только на устройстве (`localStorage`).

| Сеть | Шаги входа |
|------|-----------|
| **Telegram** | номер телефона → код подтверждения (демо-код `1111`) → привязка |
| **Instagram** | имя пользователя + пароль → код на почту (`1111`) → привязка |
| **Threads** | «Продолжить как @instagram» (если Instagram уже привязан) **или** вход по логину/паролю Instagram → код (`1111`) → привязка |

Что делает поток «завершённым»:

- единый сценарий `ввод → отправка кода → подтверждение → привязка` для всех
  трёх сетей (раньше Threads в ручном режиме пропускал шаг с кодом);
- состояние загрузки со спиннером на время имитации сетевого запроса;
- валидация: телефон Telegram, минимальная длина пароля, обязательные поля;
- таймер повторной отправки кода (30 c) с кнопкой «Отправить снова»;
- автоподтверждение по вводу 4-й цифры и кнопка «Изменить данные»;
- защита от повторной отправки во время «запроса»;
- сохранение и восстановление привязок между запусками.

Демо-код подтверждения для всех сетей — **`1111`**.

## Сборка в APK

`index.html` — единственный ассет приложения, а нативная часть
(`AndroidManifest.xml`, `classes.dex`, `resources.arsc`, иконки) не меняется.
Поэтому сборка сводится к подмене ассета, выравниванию и подписи — Gradle
и Android SDK не нужны, достаточно build-tools:

```sh
export ANDROID_BUILD_TOOLS=/path/to/android/build-tools/34.0.0
./build-apk.sh Sosv1.1.apk Sos-v1.1-auth.apk
```

Скрипт берёт скомпилированные артефакты из указанного APK-донора, кладёт рядом
текущий `index.html`, выравнивает пакет и подписывает его.

Важные детали, которые скрипт учитывает:

- `resources.arsc` и PNG-иконки укладываются **без сжатия** — при `targetSdk 34`
  сжатый `resources.arsc` ломает установку;
- подпись ставится схемами **v1 + v2 + v3**: приложение таргетит API 34, а
  начиная с Android 11 пакет только с v1-подписью не устанавливается;
- ключ создаётся один раз в `sos.jks`. **Храните его** — обновление
  устанавливается поверх, только если подписано тем же ключом.

Параметры ключа переопределяются переменными `KEYSTORE`, `KEYSTORE_PASS`,
`KEYSTORE_ALIAS`.

## Нативная часть

`MainActivity` — WebView, загружающий `file:///android_asset/index.html`.
При нажатии «назад» вызывается JS-функция `sosBack()`, которая закрывает
открытые шторки/чаты и только затем выпускает пользователя из приложения.
Манифест: `package com.sos.app`, `minSdk 21`, `targetSdk 34`, `versionName 1.1`.
